# Anarchy: instruções para o Claude

- Responda em português.
- Toda mudança feita aqui deve ir pro GitHub logo depois de pronta, sem perguntar: `git add` dos arquivos alterados, commit com mensagem curta em português e `git push origin main`.
- Nunca commitar `.env`, `desktop/servidor-padrao.json`, tokens ou chaves (já estão no `.gitignore`).
- No PowerShell, o `git` pode não estar no PATH da sessão. Antes, rode:
  `$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User')`
- Design: FigCraft via MCP (`figcraft` no `.mcp.json`, conecta no app aberto pela porta 9333). Se não conectar, abra o FigCraft com `scripts/abrir-figcraft.cmd`. Arquivos de design ficam em `design/`. Nunca mexa em arquivos abertos no FigCraft que não sejam do Anarchy.
- Servidor de casa (Windows Server, `C:\Discordia`, endereço https://win-gupi6nbu6rd.tail4f2adc.ts.net): se atualiza sozinho pela tarefa "Discordia Auto Atualizar" (`servidor-windows/auto-atualizar.ps1`), que faz `git pull` a cada 1 minuto e reinicia quando muda algo em `server/`, `servidor-windows/` ou `package*.json`. Ou seja: o push pro GitHub já é a atualização do servidor. Esta sessão não tem acesso direto ao servidor.
- App de computador: quando mudar algo em `desktop/` (ou que precise de app novo), suba a versão no `package.json`, gere com `npm run dist:cliente` e, depois de confirmar com o usuário no chat, publique no GitHub Releases (tag `vX.Y.Z`, arquivo `Anarchy-Setup.exe`). Os apps instalados baixam a versão nova sozinhos. Mudanças só em `server/public/` não precisam de app novo (chegam pelo servidor e aparece a barra "Atualizar").
- App Android (`android/`): é um WebView que abre o servidor de `desktop/servidor.json`; a ponte JS é `window.AnarchyAndroid` (notify, askNotify, call, version) e o botão voltar chama `window.anarchyBack()`. Mudanças no site chegam no celular sozinhas; só mexendo em `android/` precisa de APK novo (o APK não se atualiza sozinho: a pessoa baixa e instala por cima). Gere com `npm run dist:android` (sai em `dist/Anarchy.apk`; versão = `package.json`) e, com OK do usuário, anexe `Anarchy.apk` ao release do GitHub. As ferramentas (Java 17, Android SDK, Gradle, emulador `anarchy`) ficam em `%LOCALAPPDATA%\Anarchy-build`, junto da chave `anarchy-release.jks`; `android/keystore.properties` aponta para ela e nunca vai pro git. Sem essa chave, APKs novos não instalam por cima dos antigos. Teste no emulador com `android\gerar-apk.ps1 -Teste` (servidor local na porta 3555 + `adb reverse tcp:3555 tcp:3555`).
- Novidades: toda mudança que os usuários notam ganha um item no topo da lista `NEWS` em `server/public/app.js` (id novo, data, título, emoji e itens curtos em português simples). Quem abre o app depois vê o popup "Novidades" só com o que ainda não viu.
- Supabase: projeto `npyvvnqvtpenucqoovza` (no painel ainda pode aparecer com o nome antigo "discordia"). A função do servidor é `anarchy-db` (o servidor usa a antiga `discordia-db` enquanto a nova não existir). O schema fica em `supabase/schema.sql`; mantenha-o igual ao banco quando mudar tabelas.
